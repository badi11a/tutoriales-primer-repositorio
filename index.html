Parte 1 · Crear tu cuenta en GitHub
5 pasos

GitHub es la plataforma más usada en el mundo para guardar y compartir código. Piensa en ella como una nube especializada para proyectos de desarrollo. Más de 100 millones de desarrolladores la usan a diario.

Un detalle importante: la interfaz está solo en inglés. No existe opción oficial de cambiarla al español, por eso iremos aprendiendo los términos clave a medida que avancemos.

Acción

Abre tu navegador y ve a github.com. Haz clic en el botón Sign up que aparece arriba a la derecha.

GitHub usará este correo para enviarte un código de verificación y para notificarte sobre actividad en tu cuenta. Usa un correo que revises con frecuencia — sin verificarlo no podrás crear repositorios.

Alternativa nueva 2024+

También puedes hacer clic en Continue with Google para registrarte directamente con tu cuenta de Google, sin necesidad de crear una contraseña adicional. Si eliges esta opción, puedes saltar directamente a la Parte 2 — no habrá captcha ni correo de verificación.

El nombre de usuario aparecerá en la URL de todos tus proyectos. Por ejemplo, si tu usuario es maria-dev, tu sitio quedará en maria-dev.github.io. Elige algo profesional y fácil de recordar — este nombre te acompañará en toda tu carrera.

Evita números aleatorios o apodos informales. Muchos reclutadores revisan el perfil de GitHub como parte del proceso de selección.

GitHub presenta un rompecabezas visual que debes completar antes de continuar. Es una medida de seguridad para evitar que robots creen cuentas falsas de forma masiva. Solo toma unos segundos.

Acción

Haz clic en Start puzzle y sigue las instrucciones en pantalla para resolver el desafío visual.

GitHub envía un código de 8 dígitos al correo que ingresaste. Debes copiarlo y pegarlo en la pantalla para confirmar que el correo es tuyo. Este proceso es estándar en la mayoría de las plataformas web y se llama verificación de correo.

¿No llegó el correo? Revisa la carpeta de spam o correo no deseado. Si tampoco está, puedes solicitar que te lo reenvíen desde la misma pantalla de GitHub.

Parte 2 · Crear tu repositorio
2 pasos

Un repositorio (o "repo") es donde vive tu proyecto en GitHub. Contiene todos tus archivos y el historial completo de cambios. Puedes tener tantos repositorios como proyectos quieras — todos son gratuitos si son públicos.

Piensa en él como una carpeta inteligente en la nube que recuerda cada versión de tus archivos.

Acción

En la pantalla principal haz clic en el botón New, o en el ícono + de la barra superior y selecciona New repository.

El nombre del repositorio formará parte de la URL de tu página publicada. Si lo llamas hola-mundo, tu sitio quedará en tu-usuario.github.io/hola-mundo.

Debe ser público para que GitHub Pages funcione con una cuenta gratuita — los repositorios privados no se pueden publicar en el plan gratuito.

Acción

Escribe hola-mundo en el campo Repository name. Selecciona la opción Public y haz clic en Create repository.

Importante: deja desmarcada la casilla Add a README file. Si la marcas, el repositorio no quedará vacío y en el siguiente paso no aparecerá el enlace para subir archivos.

Usa guiones en lugar de espacios en el nombre. Los espacios no están permitidos en URLs — GitHub los convierte automáticamente en guiones de todas formas.

Parte 3 · Subir tu archivo
4 pasos

Al crear el repositorio, GitHub muestra una pantalla vacía con varias opciones para agregar archivos. La más sencilla — sin instalar nada — es subir el archivo directamente desde tu computador usando el enlace de carga que aparece en esa pantalla.

Antes de continuar: asegúrate de tener un archivo llamado index.html guardado en tu computador. Si aún no tienes uno, abre el Bloc de Notas (Windows) o TextEdit (Mac), escribe Hola Mundo y guárdalo con el nombre exacto index.html.

Acción

En la pantalla del repositorio vacío, busca y haz clic en el enlace que dice uploading an existing file. Aparece como un enlace de texto en el centro de la pantalla.

GitHub Pages busca automáticamente un archivo llamado index.html para mostrarlo como la página principal del sitio. Si el archivo tiene otro nombre, el sitio no funcionará. Puedes arrastrarlo a la zona de carga o hacer clic en el botón para buscarlo en tu computador.

El nombre debe ser exactamente index.html — todo en minúsculas, sin espacios. Una mayúscula o un espacio puede hacer que el sitio no cargue.

Un commit es como una fotografía del estado de tu proyecto en un momento específico. El mensaje describe qué cambiaste y por qué. Este historial es muy valioso: te permite saber qué se hizo, cuándo y quién lo hizo — especialmente importante cuando trabajas en equipo.

Ejemplo de buen mensaje

Escribe algo como: Agrega página principal hola mundo. Evita mensajes vagos como cambios o update.

La convención más usada es escribir el mensaje como una instrucción en presente: "Agrega", "Corrige", "Actualiza". Así el historial se lee como un registro de acciones.

Al hacer clic en Commit changes, el archivo queda guardado oficialmente en tu repositorio. GitHub registra quién hizo el cambio, cuándo y con qué mensaje. Desde este momento, el archivo vive en la nube y puedes acceder a él desde cualquier dispositivo o navegador.

Parte 4 · Publicar con GitHub Pages
4 pasos

GitHub Pages es un servicio gratuito que convierte tu repositorio en un sitio web real con una URL pública. Para activarlo debes entrar a la configuración del repositorio — no se activa de forma automática, hay que habilitarlo manualmente.

Acción

Dentro de tu repositorio, haz clic en la pestaña Settings (arriba a la derecha). En el menú lateral izquierdo, busca y haz clic en Pages.

GitHub necesita saber desde qué parte del repositorio publicar. La rama main es la rama principal donde están tus archivos. La carpeta / (root) significa la raíz del proyecto — justo donde subiste tu index.html.

Acción

En la sección Branch, selecciona main en el primer desplegable y / (root) en el segundo. Haz clic en Save.

Después de guardar, GitHub inicia un proceso automático llamado deployment (despliegue): toma tus archivos, los procesa y los publica en sus servidores. Puedes ver el estado en la misma sección de Pages — aparecerá un ícono naranja mientras procesa y verde cuando esté listo.

No cierres la pestaña. Puedes recargar la página de Settings → Pages cada 30 segundos para ver si el estado cambió a verde.

Una vez desplegado, tu sitio tiene una URL pública real que puedes compartir con cualquier persona del mundo. Esta URL sigue el formato https://tu-usuario.github.io/hola-mundo.

Desde este momento, cada vez que subas un cambio al repositorio, el sitio se actualizará automáticamente.

Tu URL

Abre una nueva pestaña y escribe: https://TU_USUARIO.github.io/hola-mundo

¿Ves un Error 404? No te asustes, es completamente normal. Significa que GitHub aún está procesando tu página. Espera dos minutos más y vuelve a presionar F5. GitHub a veces tarda un poco más en la primera publicación.

Tutorial completado

Creaste tu cuenta, subiste tu primer archivo y publicaste tu primera página en internet. Ese es el flujo base que usarás en todos tus proyectos como desarrollador.
